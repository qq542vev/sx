# bundle_test.py の検証項目と移行記録

対象は旧 `spec/build/bundle_test.py` の10個のテストです。
現在の Makefile、AGENTS.md、他のビルドテストと照合して以下の整理を行い、ShellSpec へ移行しました。
移行先は `bundle_spec.sh` と `resolve_spec.sh`、準備・後始末の補助関数は `../support/build.sh` です。
旧 Python ファイルは削除しました。後続の移行で spec 配下の残り6本も ShellSpec へ移しました。
その対応と期待値の見直しは [移行記録](python_migration.md) を参照してください。

「残す」は独立した検証目的を維持すること、「統合」は目的を維持して関連する検証にまとめること、「削除」はその期待値を今後の要件から外すことを意味します。
以下の表は移行時に採用した分類と、その理由を記録しています。

## 現在の仕様として確認できること

- make の選択引数は `SYMBOLS`、ファイル出力の引数は `OUT` です。m4 に直接指定する場合の名前は `SX_SYMBOLS` のままです。
- `SYMBOLS` が未指定・空文字列なら全単位、指定されていれば対象と依存先を生成します。
- `OUT` が未指定・空文字列なら標準出力へ出力します。`sx.sh` に保存する場合は `OUT=sx.sh` を指定します。
- 既定ターゲットと `all`、`bundle` は同じ生成処理を使い、毎回生成します。
- `make test` は全個別モジュールと全体版 `sx.sh` を生成し、`SXTEST_LOAD_MOD` を未設定にして ShellSpec を1回実行します。
- ビルド用シェルには `pipefail` 対応が必要です。検証時も対応するシェルを指定します。

## 各テストの分類と移行方針

## 個別に削除・確認する期待値

| 対象 | 判断 | 理由・残す目的 |
| --- | --- | --- |
| 単位数が必ず701である | **削除** | 単位を追加するたびに変わる値。一覧の欠落・重複は `check-units.py` と対応するテストが担当する。全単位を選択した生成結果の一致は残す。 |
| 一時ファイルが必ず出力先名の `.tmp`・`.tmp2` である | **削除** | 現在の実装が使う一時ファイル名と異なり、漏洩を検出できない。隔離した作業ディレクトリに不要ファイルが残らないという検証目的は残す。 |
| `make -n` に特定のコマンド文字列が含まれる | **削除** | 依存先へ処理を移すだけでも壊れる。全体版が生成されることと、テスト実行時の引数・環境を観測する検証へ置き換える。 |
| 全体版を読み込む ShellSpec が自動で2回目に実行される | **削除** | 現在の Makefile・AGENTS.md は、その自動実行を要求していない。 |
| `sx_uri_enc  sx_cfg_set` のような二重空白は必ず不正 | **仕様の確認が必要** | 現在の m4 は拒否するが、AGENTS.md とヘルプは「空白で区切る」とだけ記載している。この入力への期待値は保留し、形式不正の検証には変数名として明確に不正な `bad-name` を使用した。連続空白の扱いは今回変更していない。 |

## 他のテストとの関係

- `modules_spec.sh` は `module.mk` を入口に、URI 関数の生成・実行や失敗時の出力保持を検証する。bundle 側とは入口が違うため、両方を維持し、準備・検査用のシェル補助関数を共有する。
- `load_spec.sh` の主目的は `sxtest_load` の挙動。生成した実物を読み込む例は代表実行と一部重なるが、読込ヘルパーの検証を bundle 側へ移す必要はない。
- `split_globals_spec.sh` は設定値と数値派生値の初期化を検証する。4番では数値の仕様を再検証する範囲を増やさず、依存解決による部分生成を確認する。
- `split_functions_spec.sh` の全体結合検査は、一覧を直接展開して全体版と比較するもの。7・8番は選択引数を通した生成を検証するため、目的が完全に同じではない。
- 一覧や依存宣言の静的検査だけでは、m4 の依存解決処理が異常なグラフを拒否することや、関数の循環を正常に処理することまでは確認できない。3・6番の動的検証は残す。

## 移行後の構成

- `bundle_spec.sh`: 選択生成、全体生成、標準出力・ファイル出力、再生成、失敗時の既存出力保持、`make test` の呼び出し条件（24 Example）。
- `resolve_spec.sh`: 関数の循環、初期化の循環、名前の重複、不正な依存方向（5 Example）。
- `../support/build.sh`: 一時ディレクトリの準備と後始末、最小のテスト用ソースの準備、生成物の共通検査。

各 Example の目的は日本語で記述し、期待結果は ShellSpec のアサーションで確認する。標準出力・空の `OUT` のケースも追加した。
選択生成物は新しい `yash -efu -o posix` で読み込み、代表実行と `check_no_leak` による漏洩検査を行う。
`make test` の検証では最小のソースと呼び出し記録用の `shellspec` を使い、全体版・個別モジュールの生成、引数、`SXTEST_LOAD_MOD` の解除、呼び出し回数を確認する。実際の全テストは再帰実行しない。

実行方法:

```sh
shellspec spec/build/bundle_spec.sh spec/build/resolve_spec.sh
```
