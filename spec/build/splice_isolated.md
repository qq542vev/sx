# sx_arr_splice の別シェル隔離実験

```sh
shellspec spec/build/splice_isolated_spec.sh
```

ShellSpec の準備フックが一時プロジェクトへ必要なソースをコピーし、
準備用・対象用のバンドルを `make SHELL=yash SYMBOLS=... OUT=...` で生成する。
一時プロジェクトは終了時に削除する。通常の作業ディレクトリの生成物は変更しない。

準備用の新しい `yash -efu -o posix` で `sx_arr_gen` と `sx_var_dump` を使い、
入力配列だけを代入文として保存する。別の新しい `yash -efu -o posix` で
対象用バンドルと入力データを読み込む。ライブラリの設定・内部状態は転送しない。
検証側の `spec_helper.sh` は既存の `check_no_leak` を利用するために読み込む。
同ファイルはライブラリを読み込まない。

通常の3要素と、空文字・空白・単一引用符・末尾改行を含む3要素について、
復元した値、中央要素の置換結果、長さ、内部変数の漏洩を確認する。
検証側に `sx_arr_gen`・`sx_var_dump` が存在しないことも確認する。
これらは Parameters による独立したケースとして報告する。

依存欠落の対照ケースでは、一時コピー末尾の `unset -f` により
`__sx_arr_splice_raw` を取り除く。同じ検証が終了状態127で失敗し、
診断にその関数名が含まれることを確認する。元の生成物・ソースは変更しない。

これは中央要素の置換経路についての実験であり、全分岐の依存関係を保証するものではない。
`M_REQUIRE` の直接依存の照合は既存の静的検査が担当する。

旧 Python テストとの対応は [移行記録](python_migration.md) を参照する。
